# D17 — Artifact linking & resolution

- **Area:** Artifact linking & resolution (cross-cutting)
- **Date:** 2026-06-25
- **Status:** Active

## Decision
**How an agent resolves between a work item, its plan, its branch, and its PRs is a defined contract — not left to a naming convention.** Two layers. **(1) Framework convention (the fast path):** the plan markdown lives at **`/plans/<work-item-id>/plan.md`** (D10), and the **work-item ID is the join value** carried in artifacts. **Branch naming is a project responsibility, not framework** — the framework never constructs, assumes, or recognises a branch name; reaching the branch goes *through* the code PR, not by deriving a branch string. **(2) Stored pointers (the source of truth):** the plan PR and the code PR are each **linked to the ADO work item via ADO's native work-item↔PR linking** (the Azure Boards ↔ GitHub integration). **In addition**, each PR body carries a fixed, machine-parseable `AIND-LINKS` block (an HTML comment, invisible in rendered PR text) listing the **work-item URL**, the **plan path**, and — on the code PR — the **plan-PR URL**. Both are kept on purpose: the native link is the canonical pointer and the human-visible one; the in-body block is what lets a **cold agent re-grounding from artifacts only** (the PR diff/body) resolve the work item and plan **without an ADO round-trip**, keeping "re-ground from artifacts" literally true. **Resolution rules:** *forward* (have ID → plan file by the `/plans/<id>/plan.md` convention; ID → PRs by following the native links from the work item); *reverse* (have a PR → work item and plan via the native link and the `AIND-LINKS` block). **Conflict rule:** if a convention-derived guess and a stored pointer disagree, the **stored pointer (native link) wins and the agent flags it** — this is the survived-a-rename / hand-edited case. **Prerequisite (named, like D5's branch-protection rule):** the **Azure Boards ↔ GitHub integration must be connected** for native links to exist; if it is not, the degraded fallback is a fixed-prefix work-item comment (`AIND-LINK: <kind> <url>`). Native is primary, the comment is the fallback. **Failure handling (mirrors D13's merge-then-tag):** the link/back-pointer is created **after** the PR is successfully opened, so a failed link leaves a real, convention-discoverable PR rather than a dangling pointer to nothing — recoverable, never corrupt. **Scope:** entirely v0-CLI-doable under the developer's own credentials; under automation the same links are created by the service identity, contract unchanged (D6).

## Rationale
The whole cold-agent design (D7/D8/D9/D16) rests on agents re-grounding "from the merged spec," but until now nothing said how an agent handed only a work-item ID *finds* the spec, the branch, or the PR — a naming convention was silently load-bearing, and a renamed branch or hand-edited title would break the join with no detection, and there was no reverse pointer at all. A two-layer contract fixes both directions cheaply: the convention stays the fast path, and a canonical stored pointer makes reverse lookups robust and rename-proof. Native ADO links were chosen over greppable comments because they are a built-in link type (not the field/process customization D3 warned might be unavailable), they are human-auditable from the Boards UI, and they need no parsing — with the integration-connected prerequisite called out explicitly so the dependency is visible, exactly as D5 surfaces its branch-protection prerequisite. The in-body `AIND-LINKS` block is kept *as well* because a cold agent's contract is "artifacts only": it sees the PR body but does not necessarily query ADO's link API, so the in-body block is what keeps that contract honest without an extra round-trip. Branch naming is left to the project for the same reason D10 leaves the integration-branch name open — branching strategy is per-project and pinning it would impose a workflow the framework does not own — which is *why* the branch is reached through the PR rather than by deriving a name. Stored-pointer-wins-and-flags makes a rename a *detected, recoverable* event rather than a silent break, and create-link-after-PR-open makes the only possible failure a recoverable-but-discoverable item, the same shape as D13's merge-first ordering.
