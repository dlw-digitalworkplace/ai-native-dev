# D14 — Behavioral suite shape

- **Area:** Behavioral suite shape (build phase)
- **Date:** 2026-06-24
- **Status:** Superseded by D33

## Decision
**(SUPERSEDED by D33, 2026-07-09 — there is no cold test-writer and no separate behavioral suite; the coder authors tests in-context. Retained for history.)** **The cold test-writer's behavioral suite lives on the SAME branch as the implementation (one PR carries red→green), reviewed in place before the coder writes code — NOT a separate test-PR merged first.** The test-writer (D8) commits the failing behavioral suite as the first commit(s) on the code branch; a human reviews the suite **at the test-only state of the branch** — after the test-writer's commits, before any implementation commits are pushed (per D8: reviewed before the coder starts, inside the implementation phase, no new status). The coder then adds implementation to the same branch, turning the suite green, and the single code PR carries the whole red→green history. The exact PR-opening timing (review the branch at the test-only commit, or open the PR early as tests-only and review its first state) is a mechanical detail left open; it does not change the design. **Guard:** because the suite is *not* merge-frozen (it sits on the branch, where the coder could in principle weaken it), the **cold reviewer (D7/D8) treats any unexplained change to the behavioral test files as a review flag** — re-grounded from the spec, it checks the tests still match the ACs. This closes the "coder weakened the tests" gap that a merged-first test-PR would have closed by freezing. **This deliberately diverges from D10** (which chose separate-PR-merged-first for the *plan*).

## Rationale
The artifact coupling is the opposite of the plan case, so the same-branch-vs-separate-PR answer flips. The plan is *loosely* coupled to code, so D10's merge-freezing adds integrity at low cost. The behavioral suite is *tightly* coupled (same language/repo, designed to go red→green against the code), so separate-PR has high cost and low benefit here: (1) D8's independence is already enforced **structurally** (cold invocation, separate context) — it never depended on branch isolation, so freezing the suite on trunk adds little integrity; (2) merging a **red** suite to the integration branch first would break trunk CI for everyone branching off it, violating the basic "trunk is green" invariant — a real harm, not theoretical; (3) tightly-coupled artifacts want to travel and merge together, so splitting them is the unnatural move (the inverse of the plan, where splitting was natural). The reviewer-flags-test-changes guard recovers the only integrity that same-branch gives up, and it's catchable rather than silent because test-file edits appear in the same PR diff the reviewer already reads. Net: principled divergence from D10, not inheritance.
