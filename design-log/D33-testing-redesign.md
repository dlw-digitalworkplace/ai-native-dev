# D33 — Testing — redesign

- **Area:** Testing — redesign (build phase; **supersedes D8, D9, D14, D15**)
- **Date:** 2026-07-09
- **Status:** Supersedes D8, D9, D14, D15

## Decision
**Retire the cold test-writer and the live/E2E agent; testing becomes _strategy at plan time → tests authored warm by the coder → independence at the cold reviewer_.** Four moves. **(1) Remove the cold executable test-writer (D8) and its same-branch red→green machinery (D14).** Authoring meaningful *executable* tests from a frozen spec before any code exists is self-contradictory — even an "acceptance-level" test must bind to entry points/signatures that don't exist yet, so a cold author necessarily designs the code it was forbidden to design; the model was never live-validated, and its independence was already partly illusory (D14 conceded the coder can weaken a same-branch suite, backstopped only by the reviewer). **(2) Remove the live/E2E agent and the E2E gate as a first-class actor (D9/D15).** Running the app is irreducibly per-project (a project **skill**, never plugin machinery), and the automated path was already unbuildable in scope (D15). Live verification survives only as an optional **Definition-of-done line** ("needs manual live verification before merge"), satisfied by a human signal in the PR — no agent, no CI-E2E gate, no `agents/` occupant. **(3) The planner sets a per-story _test strategy_**, folded into the existing **Testing recommendations** heading + **Definition of done** (no new plan section): *whether* to test — gated on the project actually having a test practice, read from its skills/rules (a config fact, not a per-story invention; no framework ⇒ "no automated tests", the coder never bootstraps one per story, with an optional non-blocking Consideration to add one) — *at what altitude* (unit/integration/behavioral in the project's own vocabulary), and a conditional, **additive must-cover list** of edge cases/failure modes the ACs don't already state, **each with its expected outcome**, dropped entirely when the ACs already pin down testable behavior (the D23 "drop rather than fabricate filler" discipline). The planner sets *strategy*, never a designed suite. **(4) The coder authors tests warm, in-context**, against the must-cover list + the seams it builds; the **cold reviewer is the relocated independence gate.** Reviewer test mandate (added to `reviewer.md`): *coverage* — every must-cover case has a test (**blocking**); *fidelity* — each test asserts the **spec'd** outcome, not observed behavior, and the reviewer must **not** treat a green suite as evidence (**blocking**; catches assert-to-bug); *meaningfulness / anti-inflation* — tautological, framework-testing, or redundant-bulk tests (**SUGGESTION**, non-blocking). The must-cover list is the objective/taste boundary that keeps the review loop (D26) from deadlocking on test nits. **Accepted residual (stated, not papered over):** a diff-reading reviewer *reduces* both gaming (coder edits tests to pass) and inflation, it does not eliminate them; the robust mechanical upgrade — **mutation testing** — is a project-side CI gate (objective gates are CI's job, D7), named-not-built. A coder-spawned test **sub-agent is rejected** for the same seams reason: to write unit tests it must read the code, so it is cold-in-mechanism but warm-in-effect (it inherits the code's bias) while re-incurring D20's fresh-context subagent friction for zero independence gain. Status model (D4), gates, and PR mechanics are otherwise unchanged — the build phase drops two optional actors and moves test authorship into the coder with the reviewer as the check.

## Rationale
D8 rested on a contradiction the seams problem makes unavoidable: you cannot author meaningful *executable* tests against code that doesn't exist without covertly designing it — which is exactly what forced D8 to the "behavioral not unit" altitude and then D14 to same-branch red→green (a red suite can't merge to trunk first), after which D14 admitted the coder could weaken that suite and backstopped integrity with the reviewer anyway. So the *actual* anti-gaming guarantee already lived at the reviewer; D33 stops paying for brittle, unvalidated upfront machinery that provided less independence than it appeared to, and makes the reviewer's role explicit and checkable. Moving the "what to test" judgment into the planner (not a new cold agent) follows D20's settled line — an authoring role a human reviews has nothing to stay cold *from*; the independence that matters is checking the coder's *implemented* tests, which is the reviewer, grounded from the spec (the correct orientation — the code under suspicion is its input, never its ground truth). Gating "whether the project tests" on skills/rules keeps the plan domain-agnostic (D11/D23: the plan is data, not procedure) and prevents per-story framework invention. A conditional/additive must-cover list with expected outcomes gives the reviewer a spec-anchored checklist (the lever that turns "eyeball the tests" into "diff each assertion against the spec'd value") while avoiding testing filler on small stories (D23). Dropping the E2E agent matches the plugin's own portability rule — "how to run the app" is a project skill, never plugin code — and only formalises what D15 already conceded; demoting live verification to a DoD line preserves the human-signal-in-PR path with zero machinery. Rejecting a coder-side test sub-agent is the same seams argument turned on itself. Naming mutation testing as the project-side upgrade states the residual honestly, in the same spirit as D11's "rubric core is a strong default, not an enforced floor". Net: fewer actors, less unvalidated machinery, independence where it structurally holds.
