# D42 — Usage telemetry — per-phase raw tokens

- **Area:** Usage telemetry — per-phase raw tokens (work-item attachment) + time (numeric field), no cost (config/packaging side of the D1–D15 line; relates to D30, D22, D36, D41)
- **Date:** 2026-07-28
- **Status:** Active

## Decision
**Each ADO-touching phase (`/aind:intake`, `/aind:plan`, `/aind:implement`, `/aind:complete`) now records RAW usage onto the work item and nothing derived: a per-model, per-token-type token breakdown plus wall-clock time — no cost, no rate card, no rendered on-item view.** Opt-in via a `telemetry` block in `aind.settings.json` (`enabled` + an optional numeric `durationField`). A phase brackets its work with `aind-usage.sh begin` (stamps a start marker under `.aind/usage/`) and `report`; measurement is by TIMESTAMP WINDOW over the agent host's on-disk per-session events (the only place token counts exist), so attribution is per-phase even when several phases share one session. A host-aware collector (same "adapter hides the host" shape as aind-forge.sh, but on the AGENT-host axis of D22) has two backends: **Claude** reads `~/.claude/projects/<slug>/<session>.jsonl`, dedupes by `message.id` (streaming repeats it), folds in the subagent transcripts under `<session>/subagents/` (so a build total includes the reviewer passes), and reduces to a PER-MODEL map of input/output/cacheWrite/cacheRead from each message's `model`+`usage`; **Copilot** reads `~/.copilot/session-state/<session>/events.jsonl` and can only produce a single `copilot` bucket with OUTPUT tokens (its events carry no per-message model or input/cache). The token breakdown is written as the TRUTH — an append-only per-phase JSON attachment on the work item (`aind-telemetry-<id>-<phase>-<agent>-<stamp>.json`, uploaded via the `wit/attachments` REST endpoint and linked with an `AttachedFile` relation), and SECONDS accumulate into the one numeric `durationField` (queryable). New script `aind-usage.sh` (the collector + `_attach_upload`/`_attach_link` + a `_field_accumulate` primitive generalised from aind-status.sh's tag PATCH — `/fields/…` and `/relations/-` paths built INSIDE jq to dodge the MSYS leading-slash rewrite); begin/report wired into the four phase commands; `.aind/usage/` gitignored (transient markers). Best-effort throughout — a missing marker, a host that exposes nothing, missing tools, or an ADO hiccup all WARN and return 0; fully inert unless enabled (the never-disturb-the-session discipline of the D30 lessons exhaust, of which this is the tokens+time twin). **Design journey:** the first cut accumulated a single token TOTAL into one numeric field; rejected in review as (a) opaque and (b) a false cost proxy — the four token classes bill ~250× apart, so in a real session cache-reads were ~97% of tokens but only ~61% of cost. Settled, at the user's direction, on: store raw not cost, separate a durable machine-readable TRUTH from any human VIEW, and price entirely offline; the rendered on-item table/comment view considered next was then dropped outright (it only added tokens + UI clutter), leaving the attachment as the sole trace. **Offline-validated** on both backends (per-model breakdown, dedupe, subagent fold-in, timestamp-window exclusion, graceful no-op) + live transcript discovery against the real session store; then **live-validated end-to-end** on the yam testbed — intake single-tree, then implement in worktree mode, which surfaced and fixed a worktree transcript-discovery bug (the transcript is keyed to the session's launch cwd = the main checkout, so discovery must resolve via `_main_root`/git-common-dir, never `$PWD`, which points into the worktree once the shell cd's there).

## Rationale
Token/time cost is becoming a first-class factor, but the naive metric misleads: a raw token sum is dominated by cache-reads (cheap, ~0.1× input) while output (~5× input) is a sliver of the count, so no token sum equals cost — and rates differ by model/host/plan/discount and drift over time. Storing RAW usage and pricing OFFLINE lets history be re-priced anytime and keeps no formula baked into the flow (the user's explicit preference). Splitting TRUTH from VIEW is the load-bearing idea: the truth must be durable, machine-readable, and non-fragile while any human-facing rendering is disposable — so the truth is a JSON attachment and the initially-planned rendered table was cut once it was clear it only added noise. Attachment-per-phase (append-only) over one kept-current file because ADO attachments are IMMUTABLE blobs — a "single updated file" still uploads a new blob every phase AND forces a download→parse→append→re-upload→repoint-relation cycle (read-modify-write, lost-update, corruption-of-accumulated-history risk) for no saving; append-only is measure→upload→link with none of that, and each record is an immutable per-run trace (revise costs preserved). Time stays on a numeric field because it already is a clean scalar and buys native ADO queryability/rollup with no parse step. Copilot output-only is the honest limit of what its logs expose per phase; there is no cost anywhere, so its different cost economy is moot, and time is exact on both hosts. Best-effort/never-block + inert-until-opted-in mirror the D30 emission discipline. Config/packaging side of the D1–D15 line — the status model, gates, and PR contract are untouched.
