# D8 — Testing — TDD

- **Area:** Testing — TDD (point 1 of 2)
- **Date:** 2026-06-24
- **Status:** Superseded by D33

## Decision
**(SUPERSEDED by D33, 2026-07-09 — the cold test-writer and its red→green machinery are removed; tests are authored warm by the coder and checked by the cold reviewer. Retained for history.)** **Optional test-first step in the build phase, sitting between `Ready for implementation` and the coder.** **Trigger:** the **planner decides** whether a story warrants spec-level tests and records it in the plan; the human ratifies it at plan review (no new tag — rides the existing human gate). **Who writes what:** a **test-writer agent** — *cold, independent, same re-grounding contract as the reviewer (D7): re-grounded only from the merged spec + plan, never the coder's context, so it cannot be the same running session as the coder* — writes **failing behavioral / acceptance-level tests** (input→expected-behavior, tied to ACs, structure-agnostic). It does **not** write unit tests. The **coding agent** writes **unit-level tests** (warm) for the seams it creates, during implementation. **Review surface:** the behavioral suite is reviewed by a human **before implementation starts**, *inside* the implementation phase — **no separate PR and no new status** (coarse/fine split, D4: the fine-grained test review lives in the phase, the tag stays `In implementation`). **Reviewer's job shifts but does not shrink:** where a behavioral suite exists, spec-conformance is partly enforced mechanically (red→green), so the **reviewer (D7) refocuses on what tests can't express** — coding style, auth, logging, and other cross-cutting/project-rule concerns — plus the spec edge cases the suite missed; when no suite was written, the reviewer remains the sole spec-correctness check. **CI:** the test gate (previously empty) now runs the behavioral suite + the coder's unit tests. **Point 2 (live/E2E testing) is handled separately in D9.**

## Rationale
TDD's value is an *independent* executable encoding of the spec; a coder writing its own spec-tests is a mirror, not a gate (same failure mode as a warm reviewer), so the spec-test author must be cold. Behavioral (not unit) level is the test-writer's natural altitude from a *frozen spec*: unit tests presuppose implementation seams that don't exist pre-code, so a cold agent writing them would secretly design the code, constraining the coder in ways the human never reviewed — and you can't meaningfully review unit tests for code that doesn't exist (the reason the pre-impl review choice forces behavioral level). The hybrid (cold behavioral + warm units) puts independence where it counts and warmth where it's cheap, and gives full coverage overall. Keeping it optional avoids spending an agent on trivial stories; planner-decides-human-ratifies reuses the existing judgment gate instead of a lone machine tag. This finally puts something behind CI's test gate, so the cold reviewer is no longer the *only* spec-correctness check (the gap flagged in D7 / parking lot).
