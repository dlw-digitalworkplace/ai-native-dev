# D30 — Dreaming phase — implementation

- **Area:** Dreaming phase — implementation (realises D16; pins the details D16 left open)
- **Date:** 2026-07-07
- **Status:** Active

## Decision
**The dreaming phase (D16) is built: emission via a signed script, a git-native lessons store, a manual `/aind:dream` cycle with a cold dreamer subagent, and two curation gates.** Concrete choices, each an item D16 deliberately left to implementation: **(1) Store = git, on a dedicated orphan branch** `aind/lessons` (default; `AIND_LESSONS_BRANCH` optional override, GitHub-side). It never merges into integration — a pure append-only exhaust store — so lesson records never pollute a story's diff, need no branch-protection exception, and live in the same medium (git/PR) as the dreamer's output. Chosen over ADO (status lives there; config-improvement fuel belongs with config in git) and over co-locating lessons in the work PR (intake owns no branch and the cold reviewer can't commit; and a lesson gated on story-merge can't feed a cross-story cadence). **(2) Emission = one signed script** `aind-emit-lesson.sh`, called by each agent at session end — the exhaust twin of `aind-comment.sh`. It writes the record via **throwaway-index git plumbing** (`commit-tree` + `update-ref` + push, no checkout), so an agent emits mid-session without being pulled off its branch. **Human PR feedback becomes lessons through the agent that acted on it** (planner/coder revise runs already read the threads → emit `correction`/`suggestion` sourced to the thread), which realises D16's deferred human-override capture *without* a friction-adding prompt at the human gate — the tiebreak verdict the coder executes is captured as a `correction`. **(3) Record schema** = front-matter (`id`, `work_item`, `agent`, `phase`, `severity`, `source`, optional `area`) + an **Observation** body only. `severity` is a 4-value enum keyed to *degree of human intervention* — `observation`/`suggestion`/`correction`/`blocker` — the highest-value signal. **Deliberately excluded:** a *frequency* field (recurrence is the dreamer's cross-story computation, not knowable per-record) and any *suggested-fix* field (the remedy is exclusively the cold dreamer's — a pre-baked fix would anchor/contaminate the cold synthesis; the "why" the agent uniquely knows goes in the Observation instead). Lifecycle is **directory-based** (`new/` → `archive/` or `rejected/`), the single source of truth (no competing status field). **(4) Cadence = manual `/aind:dream` now, scheduled later** — the correct v0 shape (matches the manual scope of the whole flow); the *same* command becomes the scheduler's handle when an automation layer exists. **(5) Threshold = a rubric, not a counter:** the dreamer judges each cluster on **severity × recurrence × factualness** (a lone `blocker`/`correction` or a verifiable defect is actionable at n=1; a taste cluster needs recurrence), and **surfaces borderline clusters with a confidence label** rather than silently dropping them (the human prunes at review). A pure count-gate was rejected (cold-start starvation; a single human-abort is already worth acting on; the missing-eslint defect is actionable on first sight). **(6) Curation = two gates, dream-first-then-curate-clusters:** the cold dreamer clusters + judges *first* (analysis pass, no edits), the human curates the **clusters** (approve/adjust/reject — *with* the recurrence view in front of them), then the dreamer authors only the approved clusters as `.claude` edits (author pass), and the config PR is Gate 2. Curating clusters (not raw lessons) fixes the blind-spot where a human would reject a lone lesson that was actually a pattern, and is less tedious. **(7) Scope = the project's `.claude`, scope-by-default with principled carve-outs** — **Refinement (2026-07-07):** an early draft used a hardcoded folder *allowlist* (`rules/`, `skills/`, `intake-rubric.md`, project `agents/`, imported `CLAUDE.md` prose); that is brittle — it goes stale the moment a project keeps a convention in `.claude/scripts/` or `.claude/hooks/`, making a legitimate lesson about it un-actionable. Inverted to **scope = any behavior file under the project's `.claude/`** minus four carve-outs the dreamer must **never** edit (→ parking-lot instead): (a) the **flow** — status model, gates, phase sequence, and the "AIND operational rules" in `CLAUDE.md`; (b) its own **guardrails** — `settings*.json` (permissions) and any *enforcement* hook/script (signing, tag-writing), told from a benign dev hook/script by **purpose, not name**; (c) **secrets** — `aind.env`; (d) anything **outside `.claude/`** — product code, CI, infra. This is broad enough to fix a wrong build command wherever it lives (a skill *or* a project script) yet not loose: the bright line is flow+guardrails+secrets+product-code, and the permanent human PR gate backs it. Generic reusable knowledge is still a **parking-lot note** pointing at the companion standards plugin (D25), not a cross-repo PR. A suspected flow problem is a parking-lot note (`aind-dream.sh note` → durable `.aind/parking-lot.md`), never a diff. **Cold/warm split:** analysis (the judgment that must be independent) *and* authoring both sit in the cold `agents/dreamer.md` (the human gate sits between them); `/aind:dream` is the warm orchestrator that spawns it (twice) and owns the git/gh + curation mechanics — the dreamer is the one cold agent that legitimately holds `Edit`/`Write` (its output *is* a diff), an intentional asymmetry with the reviewer (a check that must never write). **New artifacts:** `scripts/aind-emit-lesson.sh`, `scripts/aind-dream.sh` (`digest`/`start`/`open-pr`/`consume`/`note`), `agents/dreamer.md` (`analyze`/`author` modes), `commands/dream.md`; `aind-common.sh` gains `aind_lessons_branch`/`aind_lessons_ref`/`aind_lessons_push`; emission wired into `intake`/`plan`/`implement`. Offline-validated (throwaway-index plumbing: emit/digest/consume/note leave the working tree untouched); live-validation pending on a testbed where a `lint` skill references an uninstalled eslint (the end-to-end probe: agent emits the defect → `/aind:dream` proposes the skill fix).

## Rationale
D16 fixed the *shape* (reflect-warm/synthesise-cold, one-PR-per-cycle, permanent human gate, config-not-flow) but left the store, record schema, cadence trigger, and pattern threshold explicitly open as tuning/implementation details — this decision closes them with the least-surprise choices given the rest of the system. Git-on-an-orphan-branch is the only store that is durable, cross-machine readable by a *cold* agent, decoupled from story-merge (so a cross-story cadence works), and in the same medium as the output PR — while keeping meta-exhaust out of product diffs. The signed-emit-script reuses the exact "mechanics-in-one-signed-script" discipline of `aind-comment.sh`/`aind-status.sh`, and the throwaway-index plumbing is what lets emission be a *session-end side effect* rather than a branch-disrupting operation. Capturing human PR feedback through the acting agent (rather than a gate prompt) is what makes D16's highest-value-but-deferred datum fall out for free. The schema exclusions are load-bearing, not minimalism: a per-record frequency would be wrong (only the dreamer sees across stories) and a per-record fix would defeat the coldness the whole phase is built around (the dreamer must originate the remedy after seeing the pattern, not rubber-stamp a warm agent's local guess). The severity-as-human-intervention enum turns the "why did a human override" signal into something groupable. Manual cadence is not a compromise but the honest v0 answer (same manual scope as D6), and it costs nothing to schedule later. The rubric-threshold (not a counter) avoids cold-start starvation and respects that a single abort or a verifiable defect is already actionable, while confidence-labelled surfacing (not silent dropping) keeps the human in control of the borderline. Dream-first-then-curate-clusters is strictly better than curate-raw-then-dream: it gives the human the recurrence view *at* the curation moment (so they don't reject a lone lesson that was a pattern) and triages ~clusters instead of ~lessons. Confining scope to the project `.claude` keeps one repo / one PR and honours the D16 boundary; parking-lot-for-generic-knowledge respects D25's separate standards plugin without inventing cross-repo PR machinery on day one. The dreamer holding `Edit`/`Write` is the defensible asymmetry with the reviewer: the reviewer must never write because writing would compromise its check; the dreamer's *entire deliverable* is a proposed diff, and its independence is preserved structurally (re-grounded from lessons + current config, spawned cold from the warm orchestrator, gated by two human reviews and the config-not-flow boundary).
