# AI-native dev flow — Design Log
Last updated: 2026-07-22
Status: **Plan phase, build phase, and dreaming phase functionally designed** (D1–D21), plus a one-time **project onboarding** step that bootstraps the config layer (D18); **all open questions resolved or descoped** (one dreaming sub-item — human-decider emission — deliberately deferred). **Near-term scope: manual execution only** (D6 amendment, 2026-06-24) — unattended automation and the service-identity question are descoped for now. Remaining work is in the parking lot (deployment, etc.) and the deferred-until-automation items, not gaps in the design. **D19→D20 (2026-06-26):** D19 trialed intake & planner as cold subagents; D20 reverted them to in-session slash commands after live testing (per-role model is achieved via per-session model choice). Net: they remain slash commands; cold subagents are reserved for the independent checks. **D21 (2026-06-29)** adds the plan-revision loop — a re-run of `/aind:plan` folds the plan PR's review feedback into the same PR. **D22 (2026-06-30)** adds **GitHub Copilot CLI as a second host** — one repo, no behavior fork (same commands/skills/scripts); a dual manifest + per-tool hooks absorb the only real incompatibility, with a bash-on-PATH prerequisite on Windows. **D23 (2026-06-30)** enriches the **plan document template** — adds a Keep-it-simple/non-goals section, conditional data contracts, a dependency-ordered task breakdown whose tasks cite the project rule files they must obey, a Considerations section, and a sourced Definition-of-done checklist — keeping the planner domain-agnostic (tasks cite `rules/*.md`, never hardcoded domains) and biased toward the simplest change; planning **and** the plan-approval path (`/aind:approve-plan`) are now live-validated. **D24 (2026-06-30)** opens the **build phase**: it packages the coding agent as a warm in-session command `/aind:implement` (per D20 — it authors, it is not an independent check), runs a single rule-driven coder (D23) with polish as its final in-context phase (D7), and scopes the **first iteration to ground→implement→polish→open the code PR** — all test authoring deferred (D8/D9), and code review, the merge gate, and the terminal tag (D7 Phase 4 / D13) held for the next iterations. **D25 (2026-06-30)** keeps AIND stack-agnostic by ruling that **generic, reusable developer guidance** (SOLID, .NET Core usage, house style, …) ships **not in AIND** but in a separate **companion dev-standards plugin** (skills), consumed via D11's two-layer pattern — the project's `rules/*.md` *reference* a standards skill and add their own exceptions/"done" bar — and wired by onboarding (D18). **D26 (2026-07-01)** builds the **code reviewer** (build-phase Phase 4): a **cold reviewer subagent** (`agents/reviewer.md`, the first `agents/` occupant) driven from **inside `/aind:implement`** — after the code PR is opened it spawns the reviewer, the **warm coder** fixes/rebuts, and it re-spawns up to **3 passes**; the reviewer checks the diff against the merged plan **and the full project rule + skill set** with a deliberately strict **CRITICAL+WARNING-block** gate (only SUGGESTION is non-blocking), posts resolvable PR threads + a summary, and never authors fixes; the tag stays `In implementation` throughout, a 3-pass deadlock escalates to a human (PR summary + signed ADO comment, tag unchanged), and **scope ends at reviewer-approval/tiebreak** — merge, the terminal tag, and all test authoring remain the next iterations. **D31 (2026-07-07)** adds a **greenfield sibling to onboarding — `/aind:kickstart`** — which bootstraps the same `.claude/` config from a guided conversation (the three lenses + operational config, plus any design docs) when there is no code to scan; identical gate and config-layer boundary to D18, a warm command reusing D18's tooling (no new scripts), with one greenfield-specific rule: an undecided point becomes a visible `TODO`, never a fabricated convention (`/aind:onboard`, re-run once code exists, reconciles the drafts). **D33 (2026-07-09)** redesigns testing and **supersedes D8, D9, D14, and D15**: the cold executable test-writer (D8) and its same-branch red→green machinery (D14) are removed (writing meaningful *executable* tests before any code exists is self-contradictory — it forces the "cold" author to design the code, and D14 already conceded the reviewer was the real integrity backstop), the live/E2E agent (D9/D15) is removed as a first-class actor (running the app is a per-project skill, never plugin machinery — surviving only as an optional Definition-of-done "manual live verification" line), and testing is re-seated as **strategy at plan time → tests authored warm by the coder → independence at the cold reviewer**: the planner records a per-story test strategy (whether — gated on the project having a test practice — at what altitude, and a conditional additive must-cover list with expected outcomes, folded into Testing recommendations + Definition of done), the coder authors the tests in-context, and the reviewer's mandate gains a test check (coverage + fidelity blocking, meaningfulness/anti-inflation as non-blocking suggestions), with mutation testing named as the project-side mechanical upgrade for the accepted residual gaming/inflation risk. Live-validated end-to-end on a real story; with it, the whole build phase (D24 + D26 + D28 + D33) is now fully live-tested. **D34 (2026-07-09)** removes **CI from the flow** as a first-class gate: AIND's objective gate is the coder getting build + tests green *before* the PR and the cold reviewer is the judgment gate, so whatever CI a project runs on the PR is orthogonal to AIND (docs-only change).

> Decisions are ordered by where they sit in the dev flow (overall shape → intake → status → planning → execution), not by when they were made.
> The **how-it-works** documentation lives in `design-doc.md`; this log holds decisions, rationale, and open items only.

Each decision is its own file in this directory; a new decision = a new `D<N>-<slug>.md` file (no shared-file edit). Files sort numerically by name; the table below preserves the dev-flow reading order.

## Open questions

*None open.* Every question raised during the design (Q1–Q10, plus the dreaming-phase questions) has been resolved by a decision or closed by descoping — see the lists below. Remaining future work lives in the **parking lot** (deployment, cost/budget, story decomposition, multi-agent splitting, plan-triage) and in the **deferred-until-automation** items called out in the decisions (the service-identity question, automation-mode merge). One **dreaming sub-item** is deliberately deferred: capturing the human decider's/merger's override reason (the human is not an agent and does not auto-emit) — see D16.

*Resolved:* Q1 (loop-back model) → **D1**. Q2 (triggers) → **D6**. Q3 (plan PR shape) → **D10**. Q4 (readiness rubric) → **D11**. Q5 (review responsibility split) → **D7**. Q6 (exception / escape hatches) → **D12** (generalized stuck-state protocol; the coder↔reviewer deadlock sub-case was already **D7**, and the v2 staleness sweep remains deferred under **D6**). Q8 (merge mechanics) → **D13** (human-gated merge + CLI tag-write in manual scope; automation-mode merge deferred). Q9 (behavioral suite shape) → **D14**, **now superseded by D33** (no separate behavioral suite — the coder authors tests in-context). Q10 (E2E execution environment) → **D15**, **now superseded by D33** (the E2E agent/gate is removed; live verification is an optional Definition-of-done line, and "how to run the app" is a per-project skill). Dreaming-phase questions (collection model, cadence, output surface, scope of authority) → **D16** (hybrid emission with cold synthesis; PR-against-`.claude`, one cycle = one PR; permanent human gate; authority bounded to the config layer).

*Closed without a decision (descoped):* Q7 (agent identity & secrets) — **closed by the D6 amendment (2026-06-24) scoping near-term execution to manual-only**, which removes any unattended agent needing a service identity. Not answered, just no longer applicable in current scope; **reopen when GitHub Actions automation is picked up** (single bot vs. per-agent, PAT vs. Entra service principal + OIDC, secret storage all still to be decided then).

## Parking lot

- Deployment pipeline specifics (out of scope for initial design)
- **Testing strategy — redesigned (D33, supersedes D8/D9/D14/D15).** Testing is now: the planner sets a per-story **test strategy** (whether/altitude/a conditional must-cover list, gated on the project having a test practice), the **coder authors the tests warm, in-context**, and the **cold reviewer** is the independence gate (coverage + fidelity blocking; meaningfulness/anti-inflation as suggestions). The cold test-writer, the same-branch red→green machinery, and the live/E2E agent are all removed; live verification survives as an optional Definition-of-done line satisfied by a human PR signal. **Accepted residual:** a diff-reading reviewer reduces but doesn't eliminate test-gaming/inflation — **mutation testing** in the project's CI is the named-not-built mechanical upgrade. Persistently-red / stuck-coder handling is still the generalized stuck-state protocol (D12), reworded to "tests don't pass" rather than "the behavioral suite isn't green".
- Multi-agent / parallel Claude Code sessions — including splitting the single coding agent or single reviewer agent into multiple skill-specific agents (project-specific; D7 models each as one for now).
- Cost / token budget considerations
- Atomic unit / story decomposition — is one US = one branch = one PR? Should the planner fan large stories into task-level PRs? Ties to ADO hierarchy.
- **Dreaming phase — designed (D16) AND built (D30).** The continuous-improvement loop is implemented: emission via `aind-emit-lesson.sh`, a git orphan-branch lessons store, a manual `/aind:dream` cycle with the cold `aind-dreamer`, and two curation gates. The items D16 left open are now pinned by D30: the **lessons-record schema** (front-matter + Observation, severity-as-human-intervention enum), the **store** (git orphan branch), the **cadence** (manual now, scheduled later), and the **pattern-vs-one-off threshold** (severity×recurrence×factualness rubric, not a counter). The **human-override capture** D16 deferred is now realised for free — human PR feedback becomes a `correction`/`suggestion` lesson via the agent that acted on it (no gate prompt). Remaining: **live end-to-end validation** (the missing-eslint `lint`-skill testbed probe); and the D25 companion-standards-plugin path is still a parking-lot note, not a cross-repo PR.
- Plan-triage step (an automated quality bar on the plan *before* human review) — deferred; human review judged sufficient for v1.
