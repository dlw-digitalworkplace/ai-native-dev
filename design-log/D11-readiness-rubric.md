# D11 — Readiness rubric

- **Area:** Readiness rubric (intake / phase 0)
- **Date:** 2026-06-24
- **Status:** Active

## Decision
**The intake agent (D2) scores stories against a two-layer, hybrid rubric stored at `.claude/intake-rubric.md`.** **Hybrid structure:** *objective* criteria are pass/fail — any miss → `Intake declined`; *judgment* criteria are raised by the agent as advisory comments on the work item, not hard fails (matching D2: the agent suggests, it does not author). **Two layers, single seeded file:** the flow ships a starter `.claude/intake-rubric.md` containing the baked-in **core**; each project edits that file in place to extend it, adding both objective *and* judgment criteria for project-specific needs (e.g. "touches payments → must cite PCI checklist"). **Core is a strong default, NOT an enforced floor** — because it is a single editable file (not a read-only merged layer), a team *can* delete core items; nothing structurally prevents it. **Baked-in core — objective (pass/fail):** title present and non-trivial; ≥1 acceptance criterion exists; intent is stated (user-story form *or* a clear problem/goal statement — "As a…" not forced rigidly); no unresolved placeholders (`TODO`/`???`/`TBD`) in body or ACs; dependencies/blockers named or explicitly "none". **Baked-in core — judgment (advisory comments):** ACs are testable/observable, not subjective ("works well"); story is single-sized, not an epic in disguise; story is internally coherent (title, intent, ACs agree); enough context for a planner to act on the *what* without guessing (the *how* is the planner's job).

## Rationale
Intake is the first and only unskippable gate (D1); without explicit criteria, `approved`/`declined` is noise and the human re-litigates every call, defeating the gate. Hybrid puts determinism where auditability matters (objective checklist) and judgment where a checkbox can't catch the real failure — a well-formatted but meaningless AC. Two-layer mirrors the existing shared-config-plus-project-rules pattern: a core so no project ships with *no* rubric, an extension so teams encode their own context. Single seeded file (Option A) chosen over an enforced read-only core (Option B) for simplicity and to trust teams — the accepted cost is that the core is a default, not an invariant; if enforcement is later needed, promote the core to a read-only merged layer. The rubric lives in-repo so the intake workflow checks it out with the rest of `.claude`, and so changing scoring criteria never touches agent logic.
