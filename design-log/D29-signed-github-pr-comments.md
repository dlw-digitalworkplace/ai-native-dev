# D29 — Signed GitHub PR comments

- **Area:** Signed GitHub PR comments (bug fix; extends the D2/D26 signing rule to the GitHub side)
- **Date:** 2026-07-06
- **Status:** Active

## Decision
**Every GitHub PR comment, review thread, and thread reply an agent posts is signed with the agent name — the same attribution ADO comments have carried since the start.** Signing was originally built only into `aind-comment.sh` (the ADO path); every PR-side posting site (`aind-thread.sh`, `aind-review-pr.sh summary`/`thread`/`reply`, `aind-revise-code-pr.sh push`, `aind-revise-plan-pr.sh push`/`reply`) posted the raw body, so on GitHub a reviewer finding and a coder rebuttal were indistinguishable. Fix: a shared `aind_gh_signature <agent>` helper in `aind-common.sh` appended by each posting site; the multi-author scripts (`aind-thread.sh`, `aind-review-pr.sh`) take an explicit `<agent>` positional (planner assumptions, reviewer findings, coder rebuttals), while the single-author revise scripts hardcode `coder`/`planner`. The machine marker on GitHub is a **real HTML comment** `<!-- AIND-AGENT: <name> -->` (GitHub preserves HTML comments and renders markdown), not the `display:none` span ADO needs (ADO strips HTML comments) — same greppable `AIND-AGENT: <name>` contract, host-appropriate carrier. **PR bodies stay unsigned** (open-plan-pr/open-code-pr): a body is the artifact, authored once, and already carries the `AIND-LINKS` marker. **No new hook:** there is no PreToolUse guard on the PR path yet (unlike ADO's `check-claude-comment.sh`) — signing holds because every PR-comment site already routes through these scripts; adding a raw-`gh pr comment` guard is a noted follow-up.

## Rationale
The signing rationale (attribution when every agent posts under one identity, D2/D26) applies verbatim to GitHub PRs: in local/v0 mode the coder, reviewer, and planner all post under the developer's single GitHub login, so without a signature the PR conversation loses track of who said what — the exact failure ADO signing was built to prevent, simply never carried across to the GitHub side when the build phase (D24/D26/D28) added PR posting. One shared helper (not per-script duplication) keeps the two hosts' signatures consistent and is where the host difference (HTML-comment vs display:none marker) is localized. Passing `<agent>` explicitly to the multi-author scripts mirrors `aind-comment.sh`'s `<agent>` arg and avoids guessing the author; hardcoding it in the revise scripts avoids interface churn where there is only ever one author. Leaving PR bodies unsigned matches their once-authored nature and avoids noise. Deferring a PR-side enforcement hook is safe for now (all sites route through the scripts) and mirrors how ADO enforcement was added after the signed path existed.
