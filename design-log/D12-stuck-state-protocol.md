# D12 — Exception handling — stuck-state protocol

- **Area:** Exception handling — stuck-state protocol (cross-cutting)
- **Date:** 2026-06-24
- **Status:** Active

## Decision
**One generalized stuck-state protocol covers every "agent cannot make progress" failure: planner can't produce a viable plan after N tries, coder can't get the behavioral suite green after N tries, and a merge conflict from concurrently landed work.** Mechanism (identical for all three): each retry loop has a fixed **attempt cap** (the actual N is a tuning detail, parked — set the mechanism now, the numbers empirically later); on hitting the cap the agent **stops** — no infinite retry, no merge, no silent exit. It sets a single shared **`AIND status - Needs attention`** tag (replacing the current status as one atomic change, per D4) and posts **what it tried and why it is stuck** as a work-item comment (planner / coder) or PR comment (coder-in-PR), so the human sees the real trail, not a synthesized summary (same principle as D7). **Merge-conflict special case:** the coder first attempts **one automated rebase/conflict-resolve**; it only escalates to `Needs attention` if that single attempt fails. **Resume:** a human resolves the blocker, then **re-triggers the phase the item was stuck in** — `Needs attention` returns to its origin phase (planner-stuck → re-run planning; coder/merge-stuck → resume build). In **v1 the human picks the right workflow to re-dispatch** (they read the comment and know whether to re-run plan or build); **v2's automatic re-routing from `Needs attention` is deferred** along with the rest of the v2 trigger work. **`Needs attention` is distinct from D7's human-tiebreaker:** D7 (agents *disagree* but are still working) deliberately does NOT move the tag — the item stays `In implementation` and the dispute lives in the PR; `Needs attention` is for an agent that has *stopped and cannot proceed*.

## Rationale
Every agent is triggered and headless — nothing watches it run — so each failure mode needs an explicit "stop and flag a human" exit, or a stuck agent loops forever burning tokens or fails silently while the item sits looking active. Generalizing D7's already-proven shape (cap → stop → escalate with visible context) to one protocol avoids three bespoke mechanisms for one problem. One shared status keeps the coarse/fine split honest (D4): the finer "which failure" is recoverable from the comment, so it doesn't need its own tag and doesn't bloat the state machine. Parking N avoids guessing empirical thresholds pre-implementation. The single automated rebase attempt handles the common trivial-conflict case cheaply without a human, while still escalating the genuine conflicts that need judgment. Returning to the origin phase (rather than a fixed restart point) is correct because the three cases are stuck at different points; v1 leans on the human-as-watchdog already assumed for triggering (D6), so no new routing machinery is needed until v2. Keeping it separate from D7 preserves the meaning of each: "we disagree, keep going" vs. "I am stuck, stop."
