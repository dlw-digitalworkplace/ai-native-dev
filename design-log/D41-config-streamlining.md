# D41 — Config streamlining — one shared checked-in settings file + a secrets-only env file, created by onboarding

- **Area:** Config streamlining — one shared checked-in settings file + a secrets-only env file, created by onboarding (config/packaging side of the D1–D15 line; relates to D18, D31, D36, D37, D39)
- **Date:** 2026-07-23
- **Status:** Active

## Decision
**Per-project config is split into two files: `.claude/aind.settings.json` — shared project config (ADO org/project, code host, repo, integration branch, branch prefixes, AND the worktree settings), **checked in** — and `.claude/aind.env` — secrets + per-user overrides only (the ADO PAT, optional `AIND_ACTOR`), **gitignored**. `/aind:onboard` and `/aind:kickstart` now *create and fill* both from guided questions and update `.gitignore`, instead of copying `.sample` files.** The `AIND_*` environment variables stay the interface every script reads, so the change is confined to the loaders: `aind-common.sh` (and `aind-preflight.sh`'s inline twin) source `aind.env` first (secrets / per-user overrides win) then jq-map `aind.settings.json` into any still-unset `AIND_*` var (CRLF-stripped; an already-set `AIND_ADO_ORG` still short-circuits the whole load for CI / parent-shell override). The worktree opt-in moves from **presence of `aind-worktree.config.json`** to an explicit **`worktree.enabled: true`** flag inside the settings file (`aind-worktree.sh` reads the nested `.worktree.*` keys; the old file is no longer read — a **clean break**, v0). `/aind:onboard` gains `AskUserQuestion` (detects code host + integration branch from the repo, asks ADO org/project + whether to enable worktrees); `/aind:kickstart` reuses the operational values it already elicits. Both **write** the filled `aind.settings.json` and a PAT-**placeholder** `aind.env` (the agent never handles the real secret) and append the gitignore lines idempotently. New template `project-template/aind.settings.sample.json`; `aind.env.sample` shrinks to secrets-only; `aind-worktree.config.sample.json` deleted; `project-template/CLAUDE.md`, README, and GETTING-STARTED updated (incl. a migration guide). **Offline-validated** (fixture: settings→`AIND_*` mapping, `aind.env`-first precedence, already-set-org short-circuit, CRLF strip, worktree toggle — 18/18) then **live-validated end-to-end** on a test project (onboard wrote both files + the gitignore line, preflight green, the flow ran through the plan/build phases). Script + docs + templates only; the status model, gates, and PR contract are untouched.

## Rationale
The old single `aind.env` mixed the one real secret with a pile of shareable project config, so a gitignored file could not carry team-shared settings, and worktree config sat in a second file behind a presence toggle — two awkward seams. Consolidating the shareable set (worktree settings included) into one checked-in JSON gives the team a single source of truth and leaves `aind.env` holding only what must stay private. Keeping the `AIND_*` env vars as the interface confines the blast radius to the two loaders — `aind-forge.sh`, `aind-status.sh`, and every other consumer are byte-for-byte unchanged (the same "commands are thin; script the mechanics" discipline as D36). Making onboarding *create and fill* the files (the user's explicit ask) closes the gap where onboard/kickstart already gathered or detected the values yet still only dropped a `.sample` for the human to copy, rename, and edit by hand. An explicit `enabled` flag was chosen over the settings file's mere presence because that file is now always present, so presence can no longer signal opt-in; the flag is also more discoverable. A clean break (over a back-compat fallback that reads the old files) fits v0 and avoids carrying dual-format loader code. PAT-as-placeholder keeps the secret out of the agent's hands. Sits cleanly on the config/packaging side of the D1–D15 line, like D18/D22/D31/D36/D37/D39.
