# D34 — Build phase — CI's place in the design

- **Area:** Build phase — CI's place in the design (relates to D7, D33)
- **Date:** 2026-07-09
- **Status:** Active

## Decision
**CI is not part of the AIND flow; remove it as a first-class flow node/gate.** The design previously drew a **CI gates** diamond between the code PR and the cold reviewer (build/lint/coverage/security/tests) with pass→reviewer and fail→coder edges. That over-stated AIND's ownership: the plugin ships no CI, configures none, and requires none — a project with no pipeline runs the flow unchanged. The **flow's own objective gate is the coder getting the project build _and_ its authored tests green _before_ opening the PR** (`/aind:implement`); the **cold reviewer** is the judgment gate. Any CI a project runs on the PR is **orthogonal** — it may re-check the same things and is where the D33 **mutation-testing** upgrade would live, but it is the project's concern, not an AIND actor. Change is **docs-only** (no code/prompt change — the coder already gated on build+tests, and nothing ever enforced CI): removed the CI node + its two edges from the diagram (`docs/index.html`), reframed the overview / Phase 3–4 prose and the glossary entry in `design-doc.md`, and reframed the README status row from "CI gates — not built" to "objective gate = pre-PR build+tests green; project CI out of scope". **D36 (2026-07-13)** makes the **code host pluggable** — the code, its PRs, and its PR comments can live in **Azure DevOps Repos** as an alternative to GitHub, selected by `AIND_CODE_HOST`, via a **forge-adapter layer** in `scripts/` that leaves `commands/`, `skills/`, and `agents/` byte-for-byte unchanged (a script-only change; git is already host-neutral, only the PR/comment API layer gets an ADO twin). **Built and live-validated end-to-end on ADO Repos** (plan→build→review→complete), shipped in v0.13.0; the render/anchoring/thread-status spikes are resolved (ADO carrier = display:none span + HTML-comment AIND-LINKS; MSYS leading-slash `filePath` fix). Implementation record in `implementation-plan-ado-code-host.md`.

## Rationale
Keeping CI in the flow implied a dependency and an ownership AIND doesn't have, and invited the reading that AIND provides/requires a pipeline. The honest picture is a clean split: **AIND enforces the objective gate _before_ the PR (coder) and the judgment gate _on_ the PR (cold reviewer); the project owns whatever CI runs alongside.** This mirrors how the flow already treats other project-owned layers (skills, `rules/*.md`, the rubric, the git host) as integration points, not plugin components. Removal (over relabelling) was chosen deliberately: a diagram node reads as "part of the system", and no "optional" label fully undoes that — the orthogonal note in glossary/prose carries the fact without implying flow membership. Nothing about the status model, gates, or PR mechanics changes.
