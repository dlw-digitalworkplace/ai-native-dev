# D32 — Intake

- **Area:** Intake (phase 0) — dependency-implementation gate (bug fix; extends D2's intake gate)
- **Date:** UNMET` line the command reads. **Gate semantics chosen to match the report:** an `UNMET` verdict (any dependency not implemented or unreadable) → **`Intake declined`**, *even at readiness score 100* — the gate is orthogonal to the rubric and **never enters the score formula** (the score reflects story-text design quality; the verdict is the sequencing gate). It is a **command-level structural gate, not a rubric criterion** (like the rubric-missing guard and the past-intake-tag check already are), so it is not scored and adds no row to the score table — it gets its own **Dependencies** section in the verdict comment naming the unmet stories. A story declined *solely* for an unmet dependency **needs no text edit**: it becomes ready when the dependency lands and the human re-runs `/aind:intake` (the report says so, so the author doesn't hunt for a non-existent story problem). **Direction is load-bearing:** only Predecessor (Dependency-Reverse) links gate — a Successor (something that depends on *this* story) does not, and Hierarchy/Related/ArtifactLink relations are ignored. **New mechanics:** `scripts/aind-deps.sh`; `commands/intake.md` gains step 4 (the gate, between scoring and posting) and the comment's Dependencies section. Offline-validated (jq predecessor-extraction picks only Dependency-Reverse from a mixed-relation fixture; the tag-value / done-state / normalize helpers unit-checked); live-validation pending against a story with a linked, unfinished predecessor.
- **Status:** Active

## Decision
**Intake now validates that a story's *dependencies are actually implemented*, not merely *named* — and an unmet dependency declines the story without touching the readiness score.** The bug: intake read the story text (rubric O5 checks only that dependencies/blockers are *named or explicitly "none"*) but never inspected the **linked** predecessor stories' status, so a well-formed story could pass intake and enter planning while a story it depends on was still unbuilt — exactly the sequencing failure the gate should prevent. Fix: a new deterministic script `scripts/aind-deps.sh <id>` resolves the item's **Predecessor** links (ADO `System.LinkTypes.Dependency-Reverse` — "must be completed before this one"), fetches each target's title + ADO state + AIND status tag, and classifies it `IMPLEMENTED` / `NOT IMPLEMENTED` / `UNKNOWN` — *implemented* = AIND status `Implementation complete`, or (for a dependency not tracked by AIND) a done-like ADO state (Closed/Done/Resolved/Completed) — emitting a final `DEPS_VERDICT: NONE
