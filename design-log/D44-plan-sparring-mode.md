# D44 — Plan co-forming: attended sparring vs headless threads (configurable run mode)

- **Area:** Planning (phase 1); config side of the D1–D15 line (relates to D5, D23, D6, D22, D41)
- **Date:** 2026-07-30
- **Status:** Active

## Decision
The plan phase gains an **attended** mode that co-forms the plan with the dev, alongside the unchanged **headless** proceed-on-assumption path. `/aind:plan` first resolves a **run mode** — `attended | headless | auto` — by precedence: an explicit command arg (`/aind:plan <id> headless`) wins, then the project default `planning.mode` in `aind.settings.json` (or the `AIND_PLAN_MODE` env var), surfaced by `aind-common.sh` and read via the new `scripts/aind-planmode.sh`; otherwise **auto** — attended when the host has `AskUserQuestion` and this isn't a headless `claude -p` run, else headless. Attended runs wrap three beats around the *unchanged* draft: **triage** (judge story size on evidence; clearly-trivial → propose a one-tap fast-track micro-plan that skips steer + spar but **never** the plan artifact or the cold review — proportionality, not exemption), **steer** (one open question for the dev's own take *before* drafting; input-not-contract, so any draft/code disagreement becomes a spar item, never a silent override), and **spar** (present the drafted *Assumptions & open questions* as one `AskUserQuestion` batch — answered items are rewritten into the plan as decisions, deferred ones stay and become threads exactly as today). The coder gains a **micro-plan escalation guard**: a fast-tracked story that grows mid-build (a new file, a data contract, a cross-cutting rule) **stops** for a full re-plan and emits a `correction` lesson. **One planning engine, two resolution channels:** attended and headless run the identical drafting process and produce the identical artifact — only *where the answers come from* differs. New/changed: `scripts/aind-planmode.sh` + the `planning.mode` config key; `commands/plan.md` (steps 1.5 + 4.5, `AskUserQuestion` in allowed-tools, optional `[attended|headless]` arg); `commands/implement.md` (the guard). Headless with no config is byte-identical to before. **Configurable mode was added from review (agtenr):** auto-detection alone is insufficient — a dev may want to force **headless** even in an interactive session (e.g. kick planning off before bed and review the PR in the morning rather than spar live), so the mode is explicitly settable (arg > config/env > auto), not merely auto-detected.

## Rationale
The plan phase was built headless-first (D6 v0, "never block waiting for an answer") — correct for automation, but it makes the *attended* experience a one-shot "make a plan" exactly when the dev is sitting there able to co-form it. Sparring turns the plan PR from "here are my guesses, argue in threads" into "here is what we decided, and the threads carry only what genuinely stayed open" — fewer threads, a higher-fidelity plan, and the dev kept as the author of intent (the steer). Triage keeps the ceremony proportional (a null-check story must not cost a full spar), and the fast-track is made safe against under-triage by the coder-side escalation guard, so proportionality never degrades into a skipped gate — the plan artifact and the cold reviewer are shrunk, never removed. This reconciles D5/D23's proceed-on-assumption doctrine rather than weakening it: the real invariant is **no *silent* decision** — headless threads each choice, attended asks it live, and neither silently drops one. Making the mode configurable (agtenr's review point) respects that "attended-capable" ≠ "wants to spar right now"; the overnight-batch case is real, and precedence arg > config > auto gives both a per-run override and a persistent per-project/per-dev default while keeping zero-config **auto** the default. The env-var-wins loader (D41) means the same `planning.mode` knob covers a checked-in team default and a one-off `AIND_PLAN_MODE=headless`. Keeping headless byte-identical preserves the automation path (D6). Copilot-host note: attended co-forming needs an `AskUserQuestion` equivalent; where the agent host lacks one it falls to headless — a capability fork on the D22 agent-host axis, not a design fork.
